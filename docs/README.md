# 분석 문서 안내

새벽배송 고객을 누구에게 어떤 상품을 제안할지의 관점으로 분석했습니다. [프로젝트 README](../README.md)를 먼저 읽고 [당시 상세 분석 기록](PROJECT_DETAILS.md)에서 방법과 산출물을 확인합니다.

## 읽는 순서

1. [상세 분석 기록](PROJECT_DETAILS.md): 고객 탐색 → 고객 등급 → 동시 구매 → 개인 추천 → 예측의 흐름.
2. [데이터 안내](../data/README.md): 아카데미 제공 자료의 구성과 공개 제한.
3. [분석 노트북 폴더](../notebooks/): 실제 분석 과정. 원본 자료는 별도로 필요합니다.

## 먼저 이해할 용어

| 용어 | 이 프로젝트에서의 뜻 |
|---|---|
| RFM | 최근 구매 시점(Recency), 구매 빈도(Frequency), 구매금액(Monetary)으로 고객을 요약합니다. |
| PCA / 로딩 | 여러 변수의 변동을 압축하는 방법 / 압축된 축에 대한 변수의 기여 계수입니다. 산출한 가중치가 매출 효과의 최적값임을 뜻하지 않습니다. |
| Apriori | 함께 구매되는 품목 조합과 연관 규칙을 찾는 방법입니다. |
| Support / Confidence / Lift | 규칙의 전체 빈도 / 조건부 구매 비율 / 독립 구매 대비 동시 구매 비율입니다. 구매를 유발하는 인과효과와 다릅니다. |
| 협업 필터링(CF) | 구매 패턴이 비슷한 사용자나 상품을 참고해 추천하는 방식입니다. |
| 코사인 유사도 | 구매 벡터의 방향이 얼마나 비슷한지 나타내는 값입니다. 추천을 받은 뒤의 만족도를 뜻하지 않습니다. |
| Sparsity | 사용자–상품 행렬에서 비어 있는 칸의 비율입니다. |
| 관측 고객매출 | 분석 기간에 실제로 관측한 고객별 매출입니다. 미래 생애가치(LTV) 추정과 구분합니다. |

## 해석 기준

분석 결과를 추천·묶음 상품 운영안으로 연결했지만, 실제 발송·도입 후 매출 상승을 검증한 결과는 아닙니다. 원본 고객별 거래를 공개하지 않습니다.
